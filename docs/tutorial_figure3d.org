* Overview

=Figure3D= (alias =MovieFigure=) is a Plotly-inspired API for rendering
interactive 3D scenes of metal-organic frameworks using Three.js.  This
tutorial walks through building a CuBTC visualization from scratch and
shows every tunable knob.

** Quick Start

#+begin_src python :exports both
from mofography.movies import Figure3D, build_static_scene
import mofography as mgr
from ase.io import read

atoms = mgr.update_with_covalent_bonds(
    read("mofography/examples/TestCIFs/P1-Cu-BTC.cif")
)
dgrid = mgr.dgrid_from_atoms_cpu(atoms, spacing=0.5).astype("float32")
seg = mgr.do_periodic_segmentation_rust(
    dgrid, atoms, spacing=0.5, mask_thickness=0.5,
    h=0.2, threshold_abs=1.5, min_distance=1.5,
    compute_connections=True, return_dgrid=False, extra_padding=5,
)

fig = build_static_scene(
    atoms,
    dgrid=dgrid,
    regions=seg["regions"],
    seg=seg,
)
fig.to_html("my_cubtc.html")
#+end_src

* Appearance — Background, Fonts, Labels

Use =set_appearance()= to control the visual chrome around the 3D scene.

** CSS Background

Any valid CSS =background= value works: solid colors, gradients, or URLs.

#+begin_src python :exports both
fig = Figure3D()

# Solid dark background
fig.set_appearance(background="#1a1a2e")

# Radial gradient (default)
fig.set_appearance(
    background="radial-gradient(circle at center, #7a7a7a 0%, #111111 100%)"
)

# Linear gradient
fig.set_appearance(
    background="linear-gradient(135deg, #0f0c29 0%, #302b63 50%, #24243e 100%)"
)
#+end_src

** Scene Background (3D viewport)

Controls the Three.js scene background behind all 3D objects.  Accepts hex
integers or hex strings.

#+begin_src python
fig.set_appearance(scene_bg=0x0a0a1a)       # dark blue-black (hex int)
fig.set_appearance(scene_bg=0xffffff)        # white
fig.set_appearance(scene_bg=0x1c1c2e)       # deep indigo
#+end_src

** Font Family & Label Size

#+begin_src python
fig.set_appearance(
    font_family='"Helvetica Neue", Arial, sans-serif',
    label_font_size=14,     # px — controls HUD checkbox labels
)
#+end_src

* Color Schemes — Using Plotly Color Palettes

The =set_colorscale()= method accepts any =px.colors.qualitative.*= palette
name or a list of color strings in Plotly format.

** Using a Plotly Palette by Name

Pass the palette name as a string — it will be resolved via
=px.colors.qualitative.<name>=.

#+begin_src python
import plotly.express as px

fig.set_colorscale("Pastel")          # px.colors.qualitative.Pastel
fig.set_colorscale("Dark24")          # px.colors.qualitative.Dark24
fig.set_colorscale("Set1")            # px.colors.qualitative.Set1
fig.set_colorscale("Bold")            # px.colors.qualitative.Bold
#+end_src

** Passing Color Lists Directly

You can also pass a list of color strings in any format Plotly uses:

#+begin_src python
fig.set_colorscale([
    "rgb(102, 197, 204)",
    "rgb(246, 207, 113)",
    "rgb(248, 156, 116)",
    "#8b5cf6",                         # hex also works
    "#22d3ee",
])

# Or pass an actual px.colors list
fig.set_colorscale(px.colors.qualitative.Vivid)
#+end_src

* Styling Individual Traces

Each =add_*= method accepts keyword arguments that override the default style.
You can also use =update_traces()= with a selector to patch existing traces.

** Framework Colors (CPK by Default)

Framework atoms use CPK coloring by default. Override with style kwargs:

#+begin_src python
# Silver metallic framework
fig.add_framework(atoms, color=[0.85, 0.85, 0.85], opacity=0.8, roughness=0.5, metalness=0.3)

# Custom per-element colors via the style dict
fig.add_framework(atoms, color=[0.9, 0.9, 0.9])
#+end_src

** Batch Updates with =update_traces=

#+begin_src python
fig.update_traces({"opacity": 0.5}, selector={"type": "mesh"})
fig.update_traces({"visible": False}, selector={"id": "surface"})
#+end_src

** Layout Deep Merge

=update_layout()= now does recursive deep merge, so nested keys are safe:

#+begin_src python
fig.update_layout({
    "scene": {
        "camera": {"eye": [3.0, 0.0, 2.0]},
    },
    "fps": 30,
})
#+end_src

* Named Style Registry

=DEFAULT_STYLES= provides named presets.  You can override at init or per-trace.

#+begin_src python
from mofography.movies import DEFAULT_STYLES
import json
print(json.dumps(DEFAULT_STYLES, indent=2, default=str))
#+end_src

Override at figure creation:

#+begin_src python
fig = Figure3D(styles={
    "framework": {"color": [0.9, 0.9, 0.9], "opacity": 0.8, "roughness": 0.5},
    "surface": {"opacity": 0.75, "roughness": 0.3},
    "internal_maxima": {"color": [1.0, 0.2, 0.2], "size": 5.0},
})
#+end_src

* Camera & Projection

** Perspective (default)

#+begin_src python
fig.set_camera(
    eye=(2.5, 0.0, 1.35),
    center=(0.0, 0.0, 0.0),
    up=(0.0, 0.0, 1.0),
    projection="perspective",
)
#+end_src

** Orthographic

#+begin_src python
fig.set_camera(
    eye=(2.5, 0.0, 1.35),
    projection="orthographic",
)
#+end_src

Users can toggle between perspective and orthographic in the viewer via the
"Toggle Orthographic" button.  Ortho mode automatically adjusts lighting,
mesh roughness, and point marker sizes for best appearance.

* Groups & Visibility

Groups let users toggle sets of traces via checkboxes in the HUD.

** Basic Groups

fig.groups["internal_pore_graph"] = {

    "label": "Internal Pore Graph",

Add =default_off: True= to hide a group at startup:

fig.groups["periodic_pore_graph"] = {

* Movie HTMLs — Animated Framework + Adsorbates

The Three.js viewer supports two kinds of movies: (1) fixed framework with
moving adsorbates, and (2) flexible framework where both framework and
adsorbates change every frame.

** Fixed-Framework Movie (One-Liner)

The framework and pore graph are computed once and stay static. Only guest
molecules animate frame-to-frame.

#+begin_src python :exports both
import mofography as mgr
from pathlib import Path

fig = mgr.make_movie_from_raspa_pdb(
    pdb_path="movie.s0.pdb",          # guest trajectory (RASPA format)
    cif_path="framework.cif",         # static framework
    out_html="movie.html",
    max_frames=200,
    spacing=0.25,
    isovalue=1.0,
    fps=20.0,
)
#+end_src

** Flexible-Framework Movie (Framework + Pores Recompute Every Frame)

When =framework_movie_path= is set, the framework mesh, unit cell,
isosurface, pore graph (maxima, windows, connections), and adsorbates are
all stored per frame.

#+begin_src python :exports both
import mofography as mgr
from pathlib import Path

base = Path("outputs/github_raspa_test")

fig, payload = mgr.make_sparse_multicomponent_movie(
    component_movie_paths={
        "benzene": base / "movies/movie.s0.pdb",
    },
    framework_movie_path=base / "Movie_IRMOF1_frameworks.pdb",
    cif_path=base / "IRMOF-1.cif",
    out_html=base / "flexible_movie.html",
    max_frames=15,
    movie_format="raspa_pdb",
    spacing=0.25,
    isovalue=1.0,
    surf_step_size=2,
    fps=20.0,
)
#+end_src

** Sidecar Streaming Mode (For Long Trajectories)

For movies with hundreds of frames, embedding all frame data in the HTML
causes browser OOM. Enable =sidecar=True= to write frame data to a
separate =.frames.jsonl= file loaded on demand.

#+begin_src python :exports both
fig, payload = mgr.make_sparse_multicomponent_movie(
    component_movie_paths={"benzene": "movie.s0.pdb"},
    framework_movie_path="frameworks.pdb",
    cif_path="IRMOF-1.cif",
    out_html="movie_streaming.html",
    sidecar=True,                     # writes movie_streaming.frames.jsonl
    max_frames=200,
    spacing=0.25,
    isovalue=1.0,
)
#+end_src

Serve both files from the same directory via any HTTP server:

#+begin_src bash
python -m http.server 8000
# then open http://localhost:8000/movie_streaming.html
#+end_src

The viewer fetches only the current frame (and one ahead/behind) via HTTP
=Range: bytes=...= requests, keeping JS heap at ~50-60 MB regardless of
total movie length. If the server does not support Range (e.g.
=python -m http.server=), the full sidecar is cached once and sliced
in-memory.

* Viewer Features (Built Into Every HTML)

Every exported HTML includes these interactive controls without any extra
Python code:

** Exploded View

Drag the "Exploded" slider to separate the framework (left), pore graph
(right), raw surface (center), PBC surface (up), and cluster surface
(down). A lightweight unit-cell copy follows each group for reference.

** Orthographic / Perspective Toggle

Click "Ortho" / "Perspective" to switch projection. Ortho mode
automatically boosts directional light intensity and contrast for clean
2D-style renders.

** Quick Axis Views

Click =+X=, =-X=, =+Y=, =-Y=, =+Z=, =-Z= to snap the camera to an axis
alignment while preserving zoom distance.

** Custom View / Light / Rotation Vectors

The HUD includes numeric vector controls:

- =View dir xyz= + =Set=: applies a normalized camera view direction while
  preserving zoom distance.
- =Dir light xyz= + =Set=: applies a normalized directional-light vector
  for the key light.
- =Rotate axis xyz=: controls the auto-rotate axis (normalized before use).

This makes camera and lighting setups reproducible for screenshots and videos.

** Video / GIF Recording

- "Record" captures WebM video via =MediaRecorder= + canvas stream.
- "REC" selects recording scale (1x/2x/3x) before recording.
- "Record GIF" (movie-mode only, when =FRAMES.length > 0=) uses =gif.js=
  from CDN. Captures up to 100 frames at 10 fps. The GIF worker is loaded
  via a Blob URL so it works even when opening the file with =file://=.

** Background Modes and Transparent PNG Export

In addition to solid color (=Bg= picker), the viewer supports gradient
background modes (L→R, T→B, radial) and a transparent mode.

- Transparent mode shows a checkerboard preview in the canvas area.
- Exported PNGs preserve alpha when transparent mode is active.

** HUD / Legend Folding

The viewer supports:

- collapsing the full HUD panel (=◧= and =Controls= tab),
- folding dynamic trace legend entries (=Fold Legend=).

** Per-Mesh Opacity Sliders

Every mesh trace (framework, surfaces) gets its own opacity slider in the
HUD. A tooltip note reminds users to turn off upper surfaces to see
through to lower ones.

** Hover Tooltips

Mouse over any atom, bond, surface face, or pore-graph node to see a
rich tooltip. Local maxima now show:
- pore radius (dgrid) in Angstroms
- segmentation region label
- maxima label and maxima PBC representative label
- maxima offset vector
- xyz coordinates and grid indices

* Comparison with the Plotly Renderer

Mofography originally used Plotly for 3D visualization. The Three.js
viewer (=MovieFigure= / =Figure3D=) replaces it for all new work. Here is
how they compare:

** Similarities

Both APIs follow the same object model:

| Concept          | Plotly                        | Three.js (=MovieFigure=)         |
|------------------+-------------------------------+------------------------------------|
| Add trace        | =fig.add_trace(go.Mesh3d(...))= | =fig.add_trace({...})=            |
| Update traces    | =fig.update_traces(...)=      | =fig.update_traces(patch, selector)= |
| Layout / camera  | =fig.update_layout(scene_camera=...)= | =fig.set_camera(eye=..., center=...)= |
| Color palettes   | =px.colors.qualitative.Pastel= | =fig.set_colorscale("Pastel")=    |
| Jupyter display  | =fig.show()=                  | =fig= (last cell expression)         |
| HTML export      | =pio.write_html(fig, ...)=   | =fig.to_html("out.html")=            |

** Differences

| Feature                | Plotly                        | Three.js (=MovieFigure=)         |
|------------------------+-------------------------------+------------------------------------|
| Rendering backend      | WebGL via stack.gl            | Three.js r128 (more mature, SSAO)  |
| Post-processing        | None                          | SSAO, ortho lighting compensation  |
| Orthographic mode      | Not supported                 | Full support with auto-lighting    |
| Exploded view          | Manual trace transforms       | Built-in 5-group slider            |
| Video/GIF recording    | External tools only           | Built-in buttons                   |
| File size (movies)     | ~300-500 MB for 50 frames      | ~100-150 MB (binary-packed sidecar) |
| RAM for long movies    | All frames in memory           | Sidecar streaming: ~50 MB fixed    |
| Mesh opacity per trace | Single opacity slider          | Per-trace opacity sliders in HUD   |
| Hover on meshes        | Not supported                  | Per-face hover with region labels  |
| Background/export UX   | Static scene bgcolor           | Solid/gradient/transparent + alpha PNG |
| Point hover priority   | First hit                      | Ranked: Points > Mesh-with-face > Lines > Instanced > Mesh |

* API Reference Summary

** Static Scene Builders

| Method                          | Description                                           |
|---------------------------------+-------------------------------------------------------|
| =build_static_scene(atoms, dgrid, regions, seg)= | One-liner for framework + segmentation + pore graph   |
| =make_framework_trace(atoms)=   | Framework mesh trace (CPK colors)                      |
| =make_surface_trace(dgrid, regions, atoms, ...)= | Isosurface mesh trace                                |
| =make_maxima_trace(seg, atoms)= | Local maxima points (internal + periodic + PBC reps) |
| =make_windows_trace(seg)=       | Window markers                                         |
| =make_connections_trace(seg, atoms)= | Pore graph edges (internal + periodic)            |
| =make_cell_trace(atoms)=        | Unit cell wireframe                                    |
| =make_guest_trace(atoms)=       | Adsorbate instanced spheres                            |
| =make_guest_bonds_trace(atoms)= | Adsorbate bond cylinders                             |

** Movie Builders

| Method                          | Description                                           |
|---------------------------------+-------------------------------------------------------|
| =make_movie_from_raspa_pdb(...)= | Fixed framework + RASPA PDB guests                    |
| =make_movie_from_trajectory(...)= | Fixed framework + any ASE-readable trajectory        |
| =make_sparse_multicomponent_movie(...)= | Flexible framework + multi-component guests      |
| =build_fixed_framework_movie(...)= | Lower-level fixed-framework movie builder             |

** Figure Mutation

| Method                          | Description                                           |
|---------------------------------+-------------------------------------------------------|
| =add_trace(trace, frame=None)=   | Add a trace dict (frame=None for static)              |
| =add_traces(traces, frame=None)= | Batch add traces                                      |
| =update_traces(patch, selector, frame)= | Merge patch into matching traces            |
| =update_layout(patch)=           | Deep-merge layout dict                                |
| =set_camera(...)=                | Set eye, center, up, projection                       |
| =set_appearance(...)=            | Set background, scene_bg, font_family, label_size     |
| =set_colorscale(colors)=         | Set surface colors from px.colors or color list       |
| =to_html(path, sidecar=False)=   | Save self-contained HTML (or sidecar pair)            |
| =show(renderer)=                 | Display in notebook or browser                        |
