* Overview
This note captures why we added a Rust AABB neighbor search for dgrid, how it is implemented for triclinic PBC (minimum image), and how it performs versus the CPU reference.

* Motivation
- Avoid O(N_grid × N_atoms) brute-force loops for distance grids.
- Reduce memory and smooth distances by querying only the nearest neighbors.
- Support non-orthogonal unit cells with full PBC/minimum-image handling.

* Implementation (Rust)
** New entry point
The new function is exported via PyO3 without touching the existing implementation:
#+begin_src rust
#[pyfunction]
#[pyo3(signature = (fpoints, cell, nx, ny, nz, radii=None, n_neighbors=10))]
fn dgrid_from_atoms_aabb(...) -> PyResult<Py<PyArray3<f32>>> { ... }
#+end_src

** PBC handling for triclinic cells
- Precompute 27 translation vectors using the full cell matrix (columns are lattice vectors).
- Replicate each atom to all images and store in an R-tree.
#+begin_src rust
let mut translations = Vec::with_capacity(27);
for tx in -1..=1 {
    for ty in -1..=1 {
        for tz in -1..=1 {
            translations.push([
                c00 * tx as f64 + c01 * ty as f64 + c02 * tz as f64,
                c10 * tx as f64 + c11 * ty as f64 + c12 * tz as f64,
                c20 * tx as f64 + c21 * ty as f64 + c22 * tz as f64,
            ]);
        }
    }
}
#+end_src

** Spatial index
We bulk-load an R-tree (rstar) with replicated atom positions; the data payload is the original atom index for radius lookup.
#+begin_src rust
let mut points: Vec<GeomWithData<[f64; 3], usize>> =
    Vec::with_capacity(fpoints.len_of(Axis(0)) * translations.len());
for (atom_idx, atom_frac) in fpoints.outer_iter().enumerate() {
    let cart = [
        c00 * atom_frac[0] + c01 * atom_frac[1] + c02 * atom_frac[2],
        c10 * atom_frac[0] + c11 * atom_frac[1] + c12 * atom_frac[2],
        c20 * atom_frac[0] + c21 * atom_frac[1] + c22 * atom_frac[2],
    ];
    for t in &translations {
        points.push(GeomWithData::new([cart[0] + t[0], cart[1] + t[1], cart[2] + t[2]], atom_idx));
    }
}
let tree = RTree::bulk_load(points);
#+end_src

** Grid traversal and distance grade
- Grid points are generated in fractional space [-0.5, 0.5] (inclusive endpoints), converted to Cartesian via the cell matrix.
- For each grid point, query the k nearest neighbors (default 10), compute Euclidean distance, subtract the atom radius, and take the minimum.
#+begin_src rust
let query = [cart_x, cart_y, cart_z];
let mut min_dist = f64::MAX;
for neighbor in tree.nearest_neighbor_iter(&query).take(n_neighbors) {
    let atom_idx = neighbor.data;
    let pos = neighbor.geom();
    let dx = pos[0] - query[0];
    let dy = pos[1] - query[1];
    let dz = pos[2] - query[2];
    let dist = (dx*dx + dy*dy + dz*dz).sqrt() - radii[atom_idx];
    if dist < min_dist { min_dist = dist; }
}
#+end_src

* Python wrapper
Added a separate wrapper to keep existing paths untouched; radii default to the same VDW table as the original wrapper.
#+begin_src python
def dgrid_from_atoms_aabb_rust(ase_atoms, spacing, radii=None, n_neighbors=10):
    if radii is None:
        radii = vdw_radii[ase_atoms.get_chemical_symbols()].values / 100.0
    fpoints = ase_atoms.get_scaled_positions() - 0.5
    cell = cellpar_to_cell(ase_atoms.cell.cellpar())
    nx, ny, nz = (ase_atoms.cell.cellpar()[:3] / spacing).astype(int) + 1
    return mgr_rust.dgrid_from_atoms_aabb(
        fpoints, cell, int(nx), int(ny), int(nz), radii, int(n_neighbors)
    )
#+end_src

* Benchmark (spacing = 0.25 Å, n_neighbors = 10)
** How it was run
Script executed from repo root (no extra files):
#+begin_src python
import numpy as np, time
from pathlib import Path
import mofography as mgr
from mofography import rust_fun
from ase.io import read

cifs = ["P1-IRMOF-1.cif","P1-Cu-BTC.cif","MIL-47-RASPA.cif",
        "NU-1000_S1.cif","LTA96.cif","DUT-75_uncapped.cif"]
base = Path("~/repos/mofography/examples/TestCIFs").expanduser()
spacing = 0.25; bins = 50
results = []
for cif in cifs:
    mat_atoms = read(base / cif)
    t0 = time.perf_counter()
    d_cpu = mgr.dgrid_from_atoms_cpu(mat_atoms, spacing=spacing,
                                     block_size=50000, precompute=True)
    t_cpu = time.perf_counter() - t0
    t1 = time.perf_counter()
    d_rust = rust_fun.dgrid_from_atoms_aabb_rust(mat_atoms,
                                                 spacing=spacing,
                                                 radii=None,
                                                 n_neighbors=10)
    t_rust = time.perf_counter() - t1
    mae = np.abs(d_cpu - d_rust).mean()
    maxe = np.abs(d_cpu - d_rust).max()
    dmin, dmax = min(d_cpu.min(), d_rust.min()), max(d_cpu.max(), d_rust.max())
    edges = np.linspace(dmin, dmax, bins + 1)
    h_cpu, _ = np.histogram(d_cpu, bins=edges, density=True)
    h_rust, _ = np.histogram(d_rust, bins=edges, density=True)
    hist_abs_diff = np.abs(h_cpu - h_rust)
    results.append((cif, t_cpu, t_rust, mae, maxe,
                    hist_abs_diff.mean(), hist_abs_diff.max()))
for r in results:
    print(r)
#+end_src

* Pitfalls / limits
** Index size
- Atoms are replicated to 27 images; R-tree size ≈ 27 × N_atoms. Very large frameworks or tiny spacing (dense grids) can stress memory.

** Grid memory dominates
- dgrid is float32 of shape (nx, ny, nz); small spacing on large cells can consume many GB regardless of neighbor search speedup.

** Neighbor count
- We always take k nearest (default 10). If atoms have large radii or local density is high, a too-small k could miss the true nearest surface; increase k in that case.

** Minimum-image scope
- 27 images assume the standard minimum-image in one unit cell. If you ever need a cutoff larger than half the shortest lattice vector (or a supercell), more images or a cutoff-aware search would be required.

** Radii validity
- Radii must be provided (or defaulted); NaNs propagate to outputs.

** Performance with skewed/long cells
- Strongly skewed or very long vectors increase index size and distance magnitudes; still correct but heavier.

* Notes
- The large max errors on some systems come from localized bins; histogram mean differences stay small.
- Speedups range ~12–34× vs CPU reference at spacing 0.25 Å.
