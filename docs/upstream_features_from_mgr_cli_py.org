* 1  Rust CIF Parser

** What changed
=mofography= previously relied entirely on ASE's pure-Python CIF reader.
The new =mofography.cif_io= module wraps a three-stage pipeline:

1. *Rust reader* (=mgr_rust.read_cif=) — parses symmetry operations, atom
   sites, and unit cell parameters directly from the CIF text without
   constructing an ASE object in Python.
2. *Wyckoff deduplication via spglib* — after symmetry expansion some CIFs
   contain duplicate sites; spglib is used to identify the asymmetric unit
   and remove duplicates before handing the structure to ASE.
3. *ASE fallback* — if the Rust reader raises (unusual CIF dialect, missing
   loop blocks) the function transparently retries with =ase.io.read=.

Under the hood the Rust code (=mgr_rust/src/cif.rs=) uses a hand-written
tokeniser that is ~15× faster than ASE on large supercells because it
avoids Python string allocation for every token.

| =mofography/cif_io.py=        | =read_cif_to_ase()=           |

* 2  Fast Covalent Bonds

** What changed
Bond detection in the original =mofography= was delegated to pymatgen's
=CovalentBond= — which iterates over a Voronoi decomposition in Python and
is slow for large unit cells.  The upstream adds a Rust implementation
(=mgr_rust.covalent_bonds=) that:

- Accepts a flat neighbor list (atom index pairs) pre-computed by any
  spatial index (AABB tree, kdtree, …).
- Applies Pauling covalent radius tolerance cutoffs in Rust.
- Returns =bonds_flat= (directed index pairs), =bond_orders= (Pauling
  estimate), per-bond =img_pos= (image-displaced Cartesian coordinates),
  and =img_an= (atomic numbers of the bonded images).

The Python wrapper =update_with_covalent_bonds()= in =analyze.py= now
tries the Rust path first; it falls back to the original pymatgen path only
if =mgr_rust= is not importable.

* 3  Aromatic Ring Expansion (Rust subgraph isomorphism)

** What changed
The Three.js viewer renders aromatic rings as flat disc meshes superimposed
over the stick bonds.  Previously, finding aromatic ring embeddings in the
bond graph was done by pure-Python networkx VF2 isomorphism — which scales
poorly (~O(N!) worst case).  The Rust implementation in =aromatic.rs= uses
petgraph's =subgraph_isomorphisms_iter= (Ullmann algorithm, backtracking
with degree-ordering pruning) and is integrated via two helpers in
=analyze.py=:

- =_sgraph_to_rust_arrays()= — serialises a networkx StructureGraph to the
  flat arrays (edge list + element labels + bond type strings) that the
  Rust function expects.
- =_expand_aromatic_embeddings_rust()= — calls =mgr_rust.expand_aromatic_cycle_embeddings=
  and maps the returned index permutations back to NetworkX node IDs.

The Three.js rendering path in =visualize.py= calls these helpers when
constructing the Three.js scene blob, so aromatic ring meshes are generated
automatically when =show_rings=True= is passed to =plot_framework_as_mesh=.

* 4  Pocket Typing (env_cluster algorithm)

** What changed
Pocket typing assigns a *chemical identity* to each segmented void region,
going beyond geometry (size, shape) to fingerprint the *local atomic
environment* of the pocket walls.  This feature was not present in
=mofography= at all before this upstream.

The algorithm (=env_cluster=):

1. For each pocket, sample voxels on a thin shell of thickness
   =mask_thickness= (default 0.05 Å) around the void surface.
2. Compute solid-angle-weighted spherical harmonic (SH) power spectra
   =P_l = Σ_m |a_{lm}|²= up to =L_max = 6= for the atoms visible from
   the shell, binned by element and by radial distance.  This gives a
   rotation-invariant fingerprint independent of the pocket's orientation.
3. Optionally augment with a *connectivity channel*: the SH spectrum of
   neighbouring pocket-center positions in the Region Adjacency Graph
   (RAG), weighted 5× because a single channel must compete with 11
   element+radial channels.  This is what allows ZIF-20's two large cage
   types — identical in size and wall chemistry — to be distinguished by
   their coordination topology (one connects to 4 windows, the other to 4
   but via a different set of saddle-point radii).
4. Cluster fingerprints hierarchically with a cosine-distance merge rule;
   merge threshold =FP_MERGE_COSINE = 0.85=.

A key design decision: =CONN_TRUST_MIN_A = 0.1 Å= (vs the physical window
trust gate =WINDOW_TRUST_MIN_A = 1.0 Å=).  ZIF-type saddle-point radii
are 0.3–0.6 Å — real topological connections that must be counted for
fingerprinting even though they are too narrow to be "windows".

* 5  Window Plotting Improvements

** 5.1  Far-outside window reclassification

** What changed
The =_serialize_windows_trace()= function in =movies.py= serialises window
(inter-pocket connection) data to the JSON payload consumed by the Three.js
scene builder.  Previously, windows whose Cartesian coordinates fell
outside the unit cell were marked as =internal= — creating phantom markers
that appeared to float far from the structure.

The fix: =_serialize_windows_trace= now accepts optional =atoms= and
=spacing= parameters.  When =atoms= is provided it checks each window
coordinate against the cell bounds (with a one-voxel tolerance); any
window more than half a voxel outside the padded cell is reclassified as
=periodic= (rendered differently in Three.js: transparent, no hover label).

** 5.2  Window marker size 8 → 10

The default =marker_size= for Plotly window scatter markers was 8.
Upstream sets it to 10 to match the =interactive_app.py= default, making
windows visible at standard zoom levels on most screens.

* 6  PLD / Percolation Window Traces

** What changed
The percolation analysis in =do_periodic_segmentation_rust= returns a
=percolation_history= list — snapshots of which pocket groups form
percolating clusters as the probe radius shrinks.  There was no way to
visualise this alongside the 3D structure in =mofography=.

Two new callables handle this:

- =plot_percolation_windows()= in =visualize.py= — produces two Plotly
  =Scatter3d= traces from a segmentation result dict:
  - *Yellow spheres* — all open inter-pocket windows.
  - *Red diamonds* — windows within =pld_tolerance= Å of the critical
    percolation radius (PLD-critical windows; these mark the tightest
    passage through the connected pore network).

- =add_percolation_windows_to_fig()= in =workflow.py= — convenience one-liner
  that calls =plot_percolation_windows= and appends the traces to an
  existing =go.Figure=.

The =percolation_history= format is a list of
=(threshold, {axis: [[region_ids, …], …]})= tuples, where axis is =x=,
=y=, or =z= — the coordinate direction along which the cluster percolates.

** Where it lives
| File                      | Symbol                           |
|---------------------------|----------------------------------|
| =mofography/visualize.py= | =plot_percolation_windows()=     |
| =mofography/workflow.py=  | =add_percolation_windows_to_fig()= |

* 7  End-to-End Workflow — Standalone HTML Figures (Plotly + Three.js)

Two high-level functions in =mofography.workflow= mirror the interactive
app's main visualisation page:

- =show_mof_plotly= — Plotly backend; returns a =go.Figure=.
  Call =fig.show()= or =fig.show(renderer="browser")= just like any
  Plotly figure.  Save to disk with =to_html(fig, ...)=.
- =show_mof_threejs= — Three.js / =MovieFigure= backend; returns
  (or writes) a self-contained HTML string.  Pass =show=True= to
  open it directly in the browser or Jupyter notebook.

Both reproduce the interactive-app default view:

| Layer | Details |
|---|---|
| Framework mesh | Ball-and-stick spheres + bonds (Taubin-smoothed) |
| Aromatic rings | Instanced torus/polygon overlays |
| Unit cell | Wire-frame box |
| Regions surface (raw) | Per-region colour from raw watershed grid |
| Regions surface (PBC merged) | Same after PBC-group merging |
| Pocket-type surface | Coloured by type id when =typed_result= supplied |
| Pore-graph connections | Edges trimmed to accessible regions |
| Windows (internal only) | Red spheres; =c[2]=="internal"= filter |
| Local maxima | Pore-centre spheres scaled by cage radius |

** Critical: keep =atoms= and =atoms_b= separate

=update_with_covalent_bonds= writes bond data into =atoms.info= in a way
that causes a Rust panic inside =assign_pocket_types=.  Keep them separate:

#+begin_example
atoms   = read_cif_to_ase(cif)                    # clean — for seg/typed
atoms_b = update_with_covalent_bonds(atoms)       # bonds — for framework only
#+end_example

Pass =framework_atoms=atoms_b= to both visualisation functions.

** Surface smoothing defaults (match interactive app)

Default =taubin_intensity = 0.05= → 3 iterations, λ=0.2175, ν=-0.2175.
Marching-cubes =step_size = 1= (full-resolution, equivalent to app “medium” quality).

Override with:

#+begin_src python
# No smoothing (sharp edges, fastest)
fig = show_mof_plotly(seg, atoms, plot_surface_taubin_smooth=False)

# Higher Taubin intensity (more blur, heavier)
fig = show_mof_plotly(seg, atoms,
                      plot_surface_taubin_iterations=8,
                      plot_surface_taubin_lambda=0.45,
                      plot_surface_taubin_nu=-0.45)

# Lower-resolution mesh (faster, larger structures)
fig = show_mof_plotly(seg, atoms, plot_surface_step_size=2)
#+end_src

** High-quality local render

When running locally (not in Spaces), you can afford =step_size=1= with
Taubin off for the sharpest surfaces — that is already the default.
For the very best quality with =stylize=True= cylinder caps, there is no
further option to set; the app’s “high” mode only adds smooth cylinders,
which =plot_framework_as_mesh= already produces by default.

* 7  Granular Three.js Figure for Large Structures (marksid-018)

** What changed
The =show_mof_threejs()= function in =workflow.py= provides a one-call
"kitchen sink" visualization, but sometimes you want granular control over
each trace — framework style, surface step size, which layers to include,
etc.  The =Figure3JS= class (and the =threejs_viz= module it wraps) exposes
the same Plotly-style =add_trace / add_traces= API for Three.js output.

This is especially useful for large structures (50K+ atoms) where the
default =mesh= framework style produces multi-GB HTML files.  Using
=scatter= or =instanced= style instead keeps the output manageable.

** Where it lives
| File                            | Symbol                     |
|---------------------------------|----------------------------|
| =mofography/threejs_viz.py=     | =Figure3JS=, =plot_surface_dgrid=, =draw_framework=, etc. |
| =mofography/workflow.py=        | =show_mof_threejs()=       |
| =mofography/movies.py=          | =MovieFigure=, =make_surface_trace= |
| =examples/gen_cubtc_granular_threejs.py= | Reference example (Cu-BTC) |

** Runnable check — marksid-018 polymer (55,286 C atoms)

This snippet reproduces the full interactive-app visualization pipeline
for the marksid-018 polymer using the granular =Figure3JS= API:

#+begin_src python
import sys, time
from pathlib import Path
import numpy as np

sys.path.insert(0, str(Path("/Users/arungopalan/repos/mofography")))
import mofography as mgr
from mofography import threejs_viz as tjs

CIF = "/Users/arungopalan/repos/mofography_manuscript/resources/mgr_org/mgr_org_scripts/marksid-018.cif"
OUT = Path("/tmp/marksid018_granular_threejs.html")
SPACING = 0.5

# ── Load ──────────────────────────────────────────────────────────────
print("Loading marksid-018...")
atoms = mgr.cif_io.read_cif_to_ase(CIF)
print(f"  {len(atoms):,} atoms")

# ── Covalent bonds (AABB neighbor list → Rust) ───────────────────────
print("Covalent bonds...")
t0 = time.perf_counter()
atoms = mgr.update_with_covalent_bonds(atoms)
print(f"  {time.perf_counter()-t0:.1f}s — {len(atoms.info['covalent_bonds']):,} bonds")

# ── Aromatic rings (large-graph fast path) ────────────────────────────
print("Aromatic rings...")
t0 = time.perf_counter()
mgr.compute_aromatic_cycles(atoms)
print(f"  {time.perf_counter()-t0:.1f}s — {len(atoms.info.get('aromatic_cycles', [])):,} cycles")

# ── Distance grid (Rust AABB) ────────────────────────────────────────
print("Distance grid...")
t0 = time.perf_counter()
dgrid = mgr.dgrid_from_atoms_rust(atoms, spacing=SPACING).astype(np.float32)
print(f"  {time.perf_counter()-t0:.1f}s — shape={dgrid.shape}")

# ── Segmentation ─────────────────────────────────────────────────────
print("Segmentation...")
t0 = time.perf_counter()
seg = mgr.do_periodic_segmentation_rust(
    dgrid, atoms, spacing=SPACING,
    mask_thickness=0.5, h=0.2,
    threshold_abs=1.5, min_distance=1.5,
    extra_padding=5, compute_connections=True,
    return_dgrid=False)
print(f"  {time.perf_counter()-t0:.1f}s")

regions        = seg["regions"]
regions_pbc    = seg["regions_pbc"]
connections    = seg["connections"]
all_maxima     = seg["all_maxima"]
unique_regions = seg["unique_regions"]
connections_trimmed = [c for c in connections
                       if np.any(np.isin(c[0], unique_regions))]

# ── Build granular Three.js figure ───────────────────────────────────
print("Building Three.js figure...")
t0 = time.perf_counter()

cscale = tjs.qualitative_colorscale("Pastel")

fig = tjs.Figure3JS(layout="dark", stylize=True)
fig.set_camera(eye=(2.0, 0.0, 1.35), center=(0, 0, 0), up=(0, 0, 1))

# Framework — "scatter" (points + lines, small file) or "instanced" (GPU spheres)
fig.draw_framework(atoms, representation="scatter")

# Unit cell wireframe
fig.plot_cell(atoms, color="orange")

# Segmentation surfaces — stepsize=2 for speed, stepsize=1 for quality
fig.plot_surface_dgrid(
    dgrid, isovalue=1.0, ase_atoms=atoms,
    region_labels=regions, name="Regions",
    opacity=1.0, cscale=cscale, stepsize=1, stylize=True)
fig.plot_surface_dgrid(
    dgrid, isovalue=1.0, ase_atoms=atoms,
    region_labels=regions_pbc, name="Regions PBC",
    opacity=0.35, cscale=cscale, stepsize=1, stylize=True)

# Maxima (distinct pore centres)
fig.plot_maxima(seg, atoms, name="Maxima", cscale=cscale)

# Channel connections
fig.plot_connections_as_it_is(
    connections_trimmed, all_maxima, dgrid.shape, atoms,
    cscale=cscale, plot_periodic=True, plot_disconnected=False)

# Windows
fig.plot_windows(
    connections_trimmed, name="Windows",
    marker_color="yellow", marker_size=10,
    marker_opacity=0.8, grid_shape=dgrid.shape, maxima=all_maxima)

# Export
fig.to_html(str(OUT))
print(f"  {time.perf_counter()-t0:.1f}s — {OUT.stat().st_size/1024/1024:.0f} MB")
print(f"Saved to {OUT}")
#+end_src
