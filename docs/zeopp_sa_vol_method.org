* Overview

This note documents how **Zeo++ 0.3** computes probe-accessible **surface area** (=-sa=) and **void volume** (=-vol=) at the CLI. Source lives in a separate checkout, typically =~/repos/zeo++-0.3/=.

Zeo++ uses a **Voronoi-network + periodic graph percolation** method for accessibility, then **Monte Carlo integration** for the reported numbers. It is **not** a voxel/lattice percolation method.

For mofography's own accessibility APIs (winding vs lattice, mesh vs MC), see =docs/accessibility_and_surface_area.org=.

* CLI entry points

| Flag | Arguments | Core function | Sampling density |
|------+-----------+---------------+------------------|
| =-sa= | =chan_radius probe_radius num_samples_per_atom [out]= | =calcASA(...)= | samples **per atom** |
| =-vol= | =chan_radius probe_radius num_samples_total [out]= | =calcAV(...)= | samples **total** in unit cell |

User-facing descriptions: =zeo++-0.3/instructions.cc= (lines ~72–80).

=main.cc= dispatches both flags with =excludePockets = true= (inaccessible pockets are *not* counted as accessible):

#+begin_src c
calcASA(&atmnet, &orgAtomnet, highAccuracy,
        chan_radius, probe_radius, calcDensity(&atmnet),
        numSamples, /*excludePockets=*/ true, output, ...);

calcAV(&atmnet, &orgAtomnet, highAccuracy,
       chan_radius, probe_radius, numSamples,
       /*excludePockets=*/ true, output, ...);
#+end_src

Related flags *not* covered here:

- =-volpo= — probe-occupiable volume (reclassifies points nominally “inside” atoms); different post-pass in =calcAV=.
- =-zsa=, =-vsa=, =-zvol=, … — same numerics with visualization output.

* Two probe radii

Both =-sa= and =-vol= take two radii:

| Parameter | Role |
|-----------+------|
| =probe_radius= | Inflates atom radii before Voronoi decomposition; defines probe–atom overlap for MC samples |
| =chan_radius= | Sets minimum throat size for **channel** accessibility on the Voronoi network |

Effective graph threshold in channel detection:

#+begin_src c
PORE::findChannelsAndPockets(&vornet,
    max(0.0, r_probe_chan - r_probe), &accessInfo, &pores);
#+end_src

(=networkaccessibility.cc=, =setupAndFindChannels=.)

When both radii are equal (common case, e.g. N₂ at 3.68 Å), the effective threshold is zero: all Voronoi edges with positive moving-sphere radius remain.

* Pipeline (shared by -sa and -vol)

#+begin_src text
  1. Inflate atom radii by probe_radius
  2. Voronoi decomposition (voro++, periodic, radial)
        → VORONOI_NETWORK + per-atom BASIC_VCELL
  3. Prune Voronoi edges where throat < chan_radius - probe_radius
  4. Build DIJKSTRA_NETWORK
  5. PORE::findChannelsAndPockets — periodic graph percolation
        → accessInfo[node] (channel vs pocket)
  6. Monte Carlo samples
        → isPointInsideAtomAndNotAccessible() per sample
  7. Integrate: fraction accessible × geometry
#+end_src

| File | Role |
|------+------|
| =main.cc= | CLI dispatch |
| =area_and_volume.cc= | =calcASA=, =calcAV=, MC loops |

* Step 1 — Voronoi decomposition

=AccessibilityClass::setupAndFindChannels= copies the atom network, adds =probe_radius= to every atom radius, then calls =performVoronoiDecomp= with voro++'s =container_periodic_poly= (=networkaccessibility.cc=, =network.cc=).

The Voronoi **nodes** (local maxima of clearance / inscribed-sphere centres) and **edges** (throat sizes as moving-sphere radii) form the void skeleton used for all later accessibility checks.

* Step 2 — Channel vs pocket (periodic percolation on Voronoi graph)

=PORE::findChannelsAndPockets(VORONOI_NETWORK*, minRadius, ...)= (=channel.cc=):

1. =vornet->prune(minRadius)= — drop edges too narrow for a sphere of diameter =2 × minRadius=.
2. =DIJKSTRA_NETWORK::buildDijkstraNetwork= — graph with periodic unit-cell displacements on edges.
3. DFS flood-fill on the graph. **Accessibility rule:** if the same node is reached again with a *different* unit-cell displacement, the component is **periodically connected** → **channel (ACCESSIBLE)**; otherwise, if the component never closes through periodic images → **pocket (INACCESSIBLE)**.

This is **graph percolation on a Voronoi skeleton**, not voxel lattice labeling.

Node-level flags land in =accessInfo=; channels and pockets get =channelMapping= / =pocketMapping= for per-channel MC statistics in the output.

* Step 3 — Classifying each MC sample point

=isPointInsideAtomAndNotAccessible= (=networkaccessibility.cc=) for every sample:

1. =find_voronoi_cell= for the sample coordinates.
2. **Inside atom?** Distance to owning atom < inflated radius → overlap (discarded for accessible count).
3. **Outside atoms:** scan Voronoi nodes in that atom's =BASIC_VCELL=; find a node with viable line-of-sight (dot-product angle test between sample ray and node ray).
4. **Accessible?** =accessInfo[nodeID]= for the matched Voronoi node.

Continuous-space MC points are therefore **projected onto the Voronoi network** for the accessibility predicate. Failed projections (numerical issues on cell faces) trigger **resampling** (=needToResampleFlag=).

For =-sa=, =removeOverlappedNodes()= is called first to drop Voronoi nodes lying inside the per-atom sampling shell.

* -vol — accessible volume

=calcAV= (=area_and_volume.cc=):

- Draw =num_samples_total= points uniformly in fractional unit-cell coordinates.
- Count samples where =!inside && !overlaps= (accessible, not in a pocket when =excludePockets=true=).

#+begin_src text
  volume_fraction = N_accessible / N_samples
  AV [Å³]         = volume_fraction × det(ucVectors)
#+end_src

Output includes AV, volume fraction, cm³/g, plus per-channel and per-pocket volume breakdowns from channel/pocket ID histograms.

* -sa — accessible surface area

=calcASA= (=area_and_volume.cc=):

- Loop over **each atom** =i=.
- For each atom, draw =num_samples_per_atom= points uniformly on a sphere of radius =(r_atom + probe_radius)= centred on the atom.
- Count shell points that are outside the atom and accessible (not in a pocket).

Per atom:

#+begin_src text
  ASA_i = (N_accessible_shell / N_samples) × 4π (r_atom + probe_radius)²
  total ASA = Σ_i ASA_i
#+end_src

Also reports NASA (non-accessible surface in pockets), and m²/cm³, m²/g using crystal density from =calcDensity=.

* -vol vs -volpo (brief)

| Flag | Accessible volume definition |
|------+------------------------------|
| =-vol= | Standard: MC point must lie outside inflated atoms and map to an accessible Voronoi node |
| =-volpo= | After the standard pass, **reclassifies** points that were “inside atoms” if they lie within =r_probe + mindist= of a nearby accessible/inaccessible MC point (=ProbeOccupiableFlag= branch in =calcAV=) |

Use =-vol= for parity with geometric accessible volume; =-volpo= is a distinct probe-occupiable estimator.

* Comparison to mofography

| Aspect | Zeo++ =-sa= / =-vol= | mofography *winding* | mofography *lattice* |
|--------+----------------------+----------------------+----------------------|
| Void geometry | voro++ Voronoi cells + network | Watershed/det segmentation + pore graph | Voxel =dgrid= mask |
| Accessibility | Voronoi graph periodic percolation | Directed graph winding percolation (+ optional window FP) | =percolation_all_axes_periodic= on voxels |
| Integration | MC (uniform in cell or on atom spheres) | MC shell or marching-cubes mesh | MC or voxel void sum |
| Pockets | Excluded when =excludePockets=true= | Winding without =window_fp=; FP bridges sub-probe windows | Separate pocket labels |
| Closest analogue | Graph percolation + MC | Same *classify then integrate* pattern, different graph | **Not** Zeo++-like — discrete lattice, not Voronoi |

**Important:** mofography's *lattice* path is a **voxel** method. Zeo++ =-sa= / =-vol= are **Voronoi-network** methods. Naming lattice “Zeo++-style” in older notes refers only to *comparison workflows*, not algorithmic identity.

Conceptual neighbour in mofography: **winding + MC** (graph-based accessibility, then Monte Carlo geometry)—but the graphs and segmentation differ, so numerical parity requires matching radii, pocket policy, and sampling counts.

* Practical notes

- *High accuracy (=-ha=)*: large atoms replaced by clusters for Voronoi; overlap checks map back to original atoms via =IDmapping=.
- *Resampling*: Voronoi face degeneracies can force redraw of MC samples; Zeo++ warns if resample count is nonzero.
- *PLD / LCD*: Zeo++ pore diameters come from the same Voronoi network (separate code paths); mofography PLD parity is documented elsewhere (=docs/pore_limiting_diameter_pld_and_percolation.md=).
- *vdW radii*: Zeo++ default radii differ from mofography's table; see =docs/vdw_radii_report.md=.
